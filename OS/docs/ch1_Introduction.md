# CH1

## 操作系统的角色与体系结构

1. 计算机系统的四个组成部分：
   
    硬件：提供最基本的计算资源，包括 CPU、内存、各类输入输出设备。
    
    操作系统：负责控制与协调底层硬件在各个应用程序和用户之间的分配与使用。
    
    系统程序与应用程序：定义了利用系统资源解决具体计算问题的方法。系统程序用于辅助系统运行和软件开发，例如命令行解释器 Bash、编译器 GCC、文件系统管理工具 mkfs 等；应用程序则是满足用户业务需求的软件，例如浏览器、文字处理软件、数据库、音视频播放器等。
    
    用户：包括普通用户、使用该系统的其他计算设备或自动化程序。

2. 操作系统的定位与核心目标：
   
    操作系统是充当用户与底层硬件之间的中介程序。
    
    其核心目标主要有三点：协助用户运行程序，降低解决计算问题的难度；让计算机系统更加方便易用；以高效率的方式合理利用计算机硬件资源。

3. 学习操作系统的动因与新兴技术：
   
    操作系统是现代计算机系统软件的基石，连接了底层算法、数据结构与上层应用。
    
    现代技术生态中许多核心方向都建立在操作系统原理之上：云计算依赖操作系统提供的大规模资源池化能力；虚拟化以及软件定义存储和网络依赖底层隔离与抽象机制；容器技术直接基于内核的命名空间 Namespace 与控制组 Cgroups 隔离技术实现；以 Hadoop 为代表的大数据生态，则是将单机操作系统的文件管理和任务调度扩展到了网络集群。

## 操作系统的定义

1. 业界并没有统一的标准定义：
   
    由于应用场景极广，学术界和工业界对操作系统没有唯一固定的定义。
    
    厂商交付视角：通常认为从厂商处获取操作系统安装介质时，所包含的整套软件都可以泛称为操作系统。这种界定差异极大，桌面操作系统附带大量图形工具和预装应用，而嵌入式系统可能只包含最基本的运行时环境。

2. 从功能角度理解操作系统的角色：
   
    资源分配器 (Resource Allocator)：计算机系统的物理硬件资源有限，面对多个并发任务提出的竞争需求，操作系统充当裁判员，负责统一管理所有资源，并在相互冲突的请求之间做出裁决，兼顾系统的吞吐效率与资源分配的公平性。
    
    控制程序 (Control Program)：负责监督和控制所有程序的执行过程，提供安全运行边界，防止因程序自身的错误或恶意操作对系统硬件及其他程序造成破坏。

3. 狭义与广义的界定：
   
    狭义的操作系统特指内核 (Kernel)，即计算机开机后始终常驻内存并持续运行的唯一程序。
    
    除了内核之外，其余所有代码在逻辑上要么属于随系统交付的系统程序，要么属于独立的应用程序。

## 计算机启动与引导过程

1. 引导程序 (Bootstrap Program)：
   
    计算机加电开机或重新启动时执行的第一段初始化代码。

2. 存放介质：
   
    引导程序通常保存在 ROM 或 EPROM 等只读非易失性芯片中，也就是常说的固件 (Firmware，如 BIOS 或 UEFI)。

3. 引导的核心任务：
   
    对计算机内部的所有硬件进行初始诊断与自检，初始化 CPU 寄存器、设备控制器和内存状态。
    
    在外部存储介质中定位操作系统的引导扇区，将操作系统内核程序加载到主存 (RAM) 中。
    
    将 CPU 执行指针跳转至内核入口地址，正式移交控制权，进入操作系统的运行循环。

## 硬件组织架构与系统运行机制

1. 基于总线的共享内存拓扑：
   
    计算机内部由一个或多个 CPU、各类设备控制器通过公共系统总线相互连接，共同访问中央共享主内存。
    
    CPU 与各类外设控制器在硬件层面是并发运行的，它们通过总线仲裁机制竞争主存访问周期。

2. 设备控制器与局部缓冲区：
   
    外部设备并不直接与 CPU 进行电气层面的交互，每类外设都由对应的设备控制器负责管理，例如磁盘控制器管理磁盘，USB 控制器管理键盘和鼠标。
    
    每个控制器内部都配备有寄存器和局部缓冲区 (Local Buffer)，用于暂存外设采集或待写入的数据。

3. 数据传输的两阶段模型：
   
    第一阶段：实际物理设备与控制器局部缓冲区之间的数据传输，由控制器硬件自动完成，完全不占用 CPU 算力。
    
    第二阶段：控制器局部缓冲区与系统主内存之间的数据搬运，可以通过 CPU 指令逐字搬运，也可以通过 DMA 控制器批量搬运。

4. 中断通报机制：
   
    控制器完成既定操作后，通过系统总线向 CPU 触发一个硬件中断信号，通知 CPU 操作已完成。

## 中断系统与处理流程

1. 操作系统由中断驱动：
   
    现代操作系统在没有事件发生时处于被动等待状态，所有硬件事件和状态流转均由中断驱动。

2. 中断向量表 (Interrupt Vector)：
   
    内存中预设的一组函数指针数组，保存了所有中断服务例程 (ISR, Interrupt Service Routine) 的入口物理地址。
    
    硬件在接收到中断信号后，根据唯一的中断号作为索引快速检索并跳转至对应的处理例程。

3. 现场保护与恢复：
   
    中断发生时，硬件必须第一时间保存当前被中断指令的地址 (即程序计数器 PC) 和关键通用寄存器的值。
    
    中断服务程序执行完毕后，系统通过恢复保存的现场信息，使原程序得以无缝继续执行。

4. 中断屏蔽机制：
   
    CPU 在处理某个中断的过程中，通常会在硬件层面暂时关闭后续中断响应，防止同类中断嵌套引发状态丢失或覆盖。

5. 广义中断的分类：
   
    硬件中断 (Interrupt)：由外部硬件设备异步触发，例如时钟脉冲到达、网卡接收到数据包、磁盘完成扇区读写等，触发时机与当前执行的指令无关。
    
    软件异常 (Exception)：CPU 执行当前指令时因内部错误同步引发，例如除以零、非法内存访问等。
    
    陷阱与系统调用 (Trap / System Call)：用户程序为了请求操作系统提供特权服务而主动执行的特殊指令，例如 RISC-V 架构下的 ecall 指令。执行后 CPU 会主动陷入内核态并跳转到指定服务例程。

## I/O 结构与 DMA 技术

1. 同步 I/O (Synchronous I/O)：
   
    CPU 发出 I/O 命令后，当前程序暂停执行，CPU 进入等待状态，必须等待该 I/O 操作彻底完成并产生中断后才返回用户程序。
    
    实现上可以让 CPU 处于闲置等待指令状态，或者通过忙等待循环持续轮询设备状态，这会持续争用总线周期。
    
    系统在同一时刻只能串行处理一个 I/O 请求，硬件利用率较低。

2. 异步 I/O (Asynchronous I/O)：
   
    CPU 发出 I/O 指令后无需等待设备处理完毕，立即返回并继续执行后续的用户程序。
    
    操作系统在内存中维护一张设备状态表 (Device-Status Table)，记录系统中每台设备的类型、端口地址以及当前工作状态。
    
    外设完成操作触发中断后，操作系统在中断例程中检索设备状态表更新状态，并唤醒正在等待该事件的阻塞程序。

3. 直接内存访问 DMA (Direct Memory Access)：
   
    面向高速 I/O 设备（如磁盘、网卡），这类设备传输速率接近主存访问速度。
    
    传统的 I/O 机制如果每传输一个字节就产生一次中断，会导致 CPU 大量耗费在中断上下文切换中。
    
    DMA 控制器能够直接接管总线，在设备控制器缓冲区与系统主内存之间批量传输数据块，整个传输过程无需 CPU 插手。
    
    核心优势在于：由原来每传输一个字节产生一次中断，优化为每传输完一个完整数据块才产生一次中断，大幅释放了 CPU 算力。

## 存储体系结构与缓存机制

1. 存储层次结构：
   
    存储系统呈金字塔分层排列，从顶到底依次为：CPU 内部寄存器、高速缓存 Cache、系统主内存 RAM、固态硬盘 SSD、机械磁盘、磁带等远级归档介质。
    
    自顶向下呈现出一致规律：访问速度逐步降低，单位容量成本逐步降低，物理存储容量逐步增大，易失性逐步向非易失性过渡。
    
    主内存是 CPU 能够通过总线直接寻址读取的唯一大型存储介质，在逻辑上可以视作辅存的最后一层缓存。

2. 机械磁盘物理组织：
   
    磁盘表面在逻辑上划分为若干同心圆磁道 (Tracks)，磁道进一步划分为扇区 (Sectors)。
    
    磁盘控制器负责处理计算机与物理盘片之间的逻辑数据交互。

3. 缓存原理 (Caching)：
   
    核心作用是解决上下两级存储介质之间巨大的速度不匹配问题 (Speed mismatch)。
    
    基于局部性原理，系统将近期频繁使用的数据从低速介质复制一份暂存在高速缓存中。读取数据时优先检查缓存，命中即可极快返回。
    
    缓存空间远小于被缓存介质，因此必须精细设计容量管理机制与替换策略 (如 LRU 最近最少使用算法)。

4. 缓存一致性问题 (Cache Coherence)：
   
    在多任务并发以及多核处理器环境下，同一份变量数据可能同时存在于主存和各个 CPU 核心的私有 Cache 中。
    
    当某一个 CPU 核心修改了其私有 Cache 中的数据时，硬件与总线必须依靠缓存一致性协议，确保其余所有 CPU 核心读取到的都是全局最新数据。

## 计算机体系结构分类

1. 对称多处理系统 SMP (Symmetric Multiprocessing)：
   
    系统中包含多个地位对等的 CPU 核心。
    
    每个处理器拥有自己独立的寄存器和局部缓存，所有处理器通过公共系统总线平等共享同一个物理主内存和 I/O 资源。

2. 多核系统 (Multicore)：
   
    将多个计算核心集成在同一块物理硅芯片上。
    
    片内核心之间的通信总线延迟明显低于板级跨芯片通信，同时具备更低的功耗与发热量。

3. 非一致性内存访问系统 NUMA (Non-Uniform Memory Access)：
   
    每个 CPU 拥有直接连接的本地内存，各个节点之间通过高速专用互联总线连接。
    
    CPU 访问自身绑定的本地内存极快，跨互联总线访问其他 CPU 节点的远端内存延迟明显增加。
    
    操作系统必须具备 NUMA 感知能力，在进程调度和内存分配时尽量让代码在本地内存运行，降低跨节点开销。

## 操作系统结构与多道分时技术

1. 多道程序设计 (Multiprogramming)：
   
    单用户单作业环境下，程序在等待慢速 I/O 时 CPU 只能处于空闲状态，整体资源利用率低下。
    
    多道程序设计在主内存中同时载入多个处于就绪状态的作业，内存空间被划分为内核驻留区与多个作业区。
    
    当正在执行的作业因等待 I/O 等事件让出 CPU 时，操作系统调度器立即切换 CPU 去执行内存中的另一个就绪作业，保证 CPU 始终处于繁忙状态，提升系统吞吐率。

2. 分时系统 (Timesharing / Multitasking)：
   
    分时系统是多道程序设计的进一步延伸，CPU 在多个处于内存的进程之间以极短的时间片轮流切换。
    
    核心追求是高度交互性 (Interactivity)，系统对每个任务的响应时间通常小于 1 秒，使每个用户在感知上如同独占整台计算机。
    
    分时系统依赖于进程抽象、CPU 时间片调度、内存交换机制 (Swapping) 以及虚拟内存机制（允许进程在没有完全载入物理内存的情况下执行）。

## 操作系统运行保护与双模式机制

1. 硬件双模式运行 (Dual-Mode Operation)：
   
    为了防止用户程序出错或恶意破坏系统，硬件提供了模式位 (Mode bit) 来区分 CPU 的特权状态。
    
    用户态 (User Mode)：运行普通用户程序，权限受到限制。
    
    内核态 (Kernel Mode / Supervisor Mode)：运行操作系统内核与驱动，拥有对底层硬件与全套指令集的完全控制权。
    
    特权指令保护：修改中断使能、配置页表基址、直接操作底层 I/O 设备等关键指令被划归为特权指令，仅允许在内核态下执行。用户态尝试执行特权指令会直接触发硬件异常。

2. 模式转换链路：
   
    用户程序需要系统服务时，通过执行系统调用指令触发陷阱，硬件将模式位自动置为内核态并跳转到内核入口。
    
    内核完成检查与服务后，执行特殊的返回指令恢复现场，并将模式位重新置回用户态，交还控制权。

3. 硬件定时器 (Timer)：
   
    用于防止用户程序因陷入死循环而无限期霸占 CPU。
    
    在将 CPU 调度给用户程序之前，操作系统会预设定时器的初值计数。硬件时钟脉冲递减该计数器，归零时强制触发时钟中断。
    
    时钟中断强制 CPU 重新回到内核态，操作系统调度器由此夺回控制权，决定是否剥夺当前进程并调度其他任务。

## 核心子系统管理职责

1. 进程管理 (Process Management)：
   
    程序是存放在存储介质上的静态指令集合，是无生命的实体；进程是程序在计算机中的一次动态执行过程，是系统分配资源与调度的基本工作单元。
    
    单线程进程拥有一个独立的程序计数器 PC，按序执行；多线程进程在共享地址空间的同时，每个线程各拥有独立的程序计数器。
    
    操作系统的管理活动包括：进程的创建与终止、进程状态挂起与恢复、提供进程同步机制（如互斥锁与信号量）、提供进程间通信机制 IPC、提供死锁预防与解除机制。

2. 内存管理 (Memory Management)：
   
    代码和数据必须加载到内存中才能被 CPU 寻址并执行。
    
    操作系统的管理活动包括：精确跟踪物理内存中哪些区域已被使用以及被哪个进程使用；在内存不足时决定将哪些进程或页面换入换出；负责动态分配与回收物理内存空间；提供虚拟内存地址转换与内存隔离保护。

3. 存储与文件系统管理 (Storage Management)：
   
    操作系统通过文件 (File) 这一抽象概念，屏蔽底层磁盘、磁带、闪存等不同物理介质的电磁特性，向上提供统一的逻辑存储视图。
    
    文件系统职责包括：文件与目录的创建、删除、修改与读写定位原语；文件访问权限控制；将文件逻辑地址映射到底层实际物理块；元数据与文件备份机制。
    
    辅存管理职责包括：磁盘空闲块空间管理、物理块分配策略、磁盘磁头寻道调度算法。

4. I/O 子系统 (I/O Subsystem)：
   
    向用户和上层应用隐藏特定外部设备的差异与操作怪癖。
    
    负责 I/O 内存管理：包括缓冲 (Buffering，在传输中临时存取数据以解决速度不匹配)、缓存 (Caching，暂存频繁使用的数据提高性能)、假脱机 (Spooling，通过磁盘队列重叠作业输入输出，虚拟化慢速独占设备)。
    
    提供标准通用的设备驱动程序接口，以及针对具体外设的专用驱动实现。

## 操作系统设计原则与 RISC-V 核心寄存器

1. 操作系统的根本设计原则：
   
    抽象 (Abstraction)：将底层硬件细节封装为清晰易用的接口模型，例如将 CPU 抽象为进程、将物理内存抽象为虚拟地址空间、将磁盘抽象为文件系统。
    
    多路复用 (Multiplexing)：在时间维度（分时共享）与空间维度（分块共享）上复用硬件资源，支持多任务并发。
    
    隔离保护 (Isolation)：确保不同应用程序之间以及应用程序与内核之间强隔离，单一程序崩溃不影响整体系统。
    
    资源共享 (Sharing)：在安全可控的前提下，支持多个程序共享数据与物理资源。
    
    高性能与通用性 (Performance & Range of uses)：以尽可能低的系统开销驱动硬件，支撑多样化的上层计算需求。

2. 衔接实验的 RISC-V 核心寄存器体系：
   
    通用寄存器文件：包含 32 个通用寄存器 (x0 至 x31)。其中 x0 恒为 0；ra 为函数返回地址寄存器；sp 为栈指针寄存器；gp 与 tp 分别为全局指针与线程指针；a0 至 a7 用于函数调用与系统调用参数传递；s0 至 s11 为被调用者保存寄存器；t0 至 t6 为临时寄存器。
    
    控制与状态寄存器 (CSRs)：用于特权级切换与中断异常控制。sstatus 记录当前特权模式与全局中断使能；sie 与 sip 分别控制中断使能与查询中断挂起状态；stvec 保存陷阱处理程序的基地址；scause 记录引发陷阱的具体原因代码；sepc 在陷入 S 态时自动保存中断发生处的 PC 地址；stval 记录出错的虚拟内存地址或指令代码；satp 保存页表基地址并控制硬件分页机制的开启。
