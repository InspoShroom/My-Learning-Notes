# ch4 Primitive Attributes

本章节前半部分主要讲OpenGL如何将一个图元画到屏幕上，包括类型、命令写法、颜色、点线面的现实属性等；后半部分主要讲区域填充的实现、锯齿现象与抗锯齿技术、二维裁剪算法等。

## OpenGL 图元与绘制流程

1. **绘制的三个阶段**

    我们把 OpenGL 程序归纳成三件事：

    - 在世界场景中定义物体，也就是给出顶点坐标；
    - 设置建模变换与观察变换，把物体放到相机能看到的位置；
    - 渲染场景，把几何数据送进管线变成像素。

    前两阶段的产物是几何数据，第三阶段才是真正决定屏幕上出现什么。属性参数属于第三阶段，它决定了同样的几何形状最终长成什么样子。

2. **属性参数与组织方式**

    属性：同一个正方形，有不同的颜色、不同粗细、不同填充方式，这就是属性。

    两种设置思路：

    - 让每个图元自带属性，在C++中就是给图元对象挂一个属性的结构体，绘制时一起传入；
    - 让图形系统持有状态，即OpenGL的实现方式；

    OpenGL 是一个**状态机**。属性通过状态函数设置一次后一直生效，影响之后所有绘制命令，直到再次被修改。所以理解 OpenGL 程序的关键不是背函数名，而是理解当前状态是什么。

3. **图元类型**

    这里主要将图元分为点、线、面三类：

    - `GL_POINTS`：每个顶点单独画一个点；
    - `GL_LINES`：每两个顶点组成一条独立线段；
    - `GL_LINE_STRIP`：顶点依次相连成折线，不闭合；
    - `GL_LINE_LOOP`：和折线一样，但首尾自动相连闭合；

    

    - `GL_TRIANGLES`：每三个顶点组成一个三角形；
    - `GL_POLYGON`：一个多边形，顶点必须按顺序给出。
    - `GL_QUADS`：每四个顶点组成一个四边形；
    - `GL_TRIANGLE_STRIP`：三角形条带，第 i 个三角形由顶点 i、i+1、i+2 组成，相邻三角形共边，n 个顶点画 n-2 个三角形；
    - `GL_TRIANGLE_FAN`：三角形扇形，所有三角形共享第一个顶点，n 个顶点画 n-2 个三角形；
    - `GL_QUAD_STRIP`：四边形条带；

    <img src="./assets/ch4/image-20261111133204236.png" alt="image-20261111133204236" style="zoom: 33%;" />

    两条提示：

    1. 实际工程中真正常用的只有 `GL_TRIANGLES` 和 `GL_POLYGON`，其余都是它们的组织变体；
    2. 合法的 OpenGL 多边形必须闭合、凸、共面、不自交。三角形天生满足全部四条，所以三角形是唯一绝对安全的图元。

    条带类图元的每个四边形也要求共面且凸，否则光栅化结果不可预期。

4. **命令命名规范**

    OpenGL 的函数名、数据类型等有固定规律，我们通过看名字还能知道参数类型：

    - 函数：所有函数以 `gl` 开头，例如 `glVertex3f`；
    - 常量：全大写并以 `GL_` 开头，例如 `GL_COLOR_BUFFER_BIT`；
    - 数据类型：以 `GL` 开头，例如 `GLfloat`；
    - 参数：
    	1. 函数名末尾的两个字符表示参数的数据类型与个数，例如 `glVertex3f` 表示接受三个 `GLfloat`；
    	2. 末尾带 `v` 表示参数是一个数组指针，例如 `glVertex3fv(a)` 等价于把 `a[0]`、`a[1]`、`a[2]` 传进去。

5. **顶点与 glBegin / glEnd**

    所有图元都由顶点定义，顶点由 `glVertex` 系列函数给出，可以带两维、三维或四维坐标。图元则用 `glBegin` 指定类型，把一组顶点框在 `glBegin` 与 `glEnd` 之间。

    ```c
    glBegin(GL_POLYGON);
        glVertex3f(1.0, 2.0, 0.0);
        glVertex3f(0.0, 0.0, 0.0);
        glVertex3f(3.0, 0.0, 0.0);
        glVertex3f(3.0, 2.0, 0.0);
    glEnd();
    ```

    同一组顶点换一个 `glBegin` 的参数，画出来的东西完全不同，用 6 个顶点对比三种线图元：

    ![image-20261111133806090](./assets/ch4/image-20261111133806090.png)

    > 这里的`glVertex2v`应该有误，正确写为`glVertex2fv`，有`v`的情况就必须要带类型字母。
    
    在移动端和现代 OpenGL 中，这套立即模式已经被废弃。OpenGL ES 没有 `glBegin`、`glVertex`、`glEnd`，改用顶点数组加 `glDrawArrays`：
    
    ```c
    glEnableVertexAttribArray(0);
    glVertexAttribPointer(VERTEX_ARRAY, GL_FLOAT, GL_FALSE, afVertices);
    glDrawArrays(GL_TRIANGLE_STRIP, 0, 4);
    ```
    
    差别在于顶点数据一次性上传给显卡，驱动程序不再逐顶点调用函数，开销大幅下降。这一点和第三章提到的 Vulkan、Metal 把控制权下放给应用是同一个方向。
    
    - 图元绘制示例
    
    	比方说画一个立方体结构，那么先按面算出8个顶点的坐标，再为每个面写一个`glBegin(GL_POLYGON)` 块，用 `glVertex3fv` 引用顶点数组。
    
    	另一个例子是用条带拼出球体，这个例子说明了为什么需要条带类图元。球体按经纬度参数化，中间主体用 `GL_QUAD_STRIP`，每一圈纬度对应一对相邻的顶点环，逐段拼成四边形带；两极退化成一个点，用 `GL_TRIANGLE_FAN` 围绕极点扇出一个圆盘。代码结构是两层循环，外层遍历纬度 $\phi$，内层遍历经度 $\theta$，把球面坐标换算成直角坐标：
    
    	```c
    	c = M_PI / 180.0;                    // 角度转弧度
    	for (phi = -80.0; phi <= 80.0; phi += 20.0) {
    	    glBegin(GL_QUAD_STRIP);
    	    for (theta = -180.0; theta <= 180.0; theta += 20.0) {
    	        glVertex3d(sin(c*theta)*cos(c*phi), cos(c*theta)*cos(c*phi), sin(c*phi));
    	        glVertex3d(sin(c*theta)*cos(c*(phi+20.0)), cos(c*theta)*cos(c*(phi+20.0)), sin(c*(phi+20.0)));
    	    }
    	    glEnd();
    	}
    	```
    
    	这段代码配合 `glPolygonMode(GL_FRONT_AND_BACK, GL_LINE)` 就画出课件里那张线框球。它同时暴露了条带图元的约束：球面本身是曲面，用四边形带逼近时每一小片都近似共面，纬度分得越细逼近越好，但每一片仍然必须是凸的平面四边形，否则光栅化结果会出问题。
    
6. **颜色设置**

    OpenGL 的颜色用 RGB 三个分量表示，每个分量是 0.0 到 1.0 的浮点数。

    - 背景色用 `glClearColor` 设置，再用 `glClear(GL_COLOR_BUFFER_BIT)` 真正清屏；
    - 物体颜色用 `glColor3f` 设置。

    ```c
    glClearColor(0.0, 0.0, 0.0, 0.0);   // 黑背景
    glClear(GL_COLOR_BUFFER_BIT);
    glColor3f(1.0, 1.0, 1.0);           // 白色物体
    ```

    `glBegin` 与 `glEnd` 之间能写的命令是有限制的，课件明确列出可以写的有 `glColor`、`glNormal`、`glTexCoord`、`glMaterial`。原因是这些命令都属于逐顶点属性，顶点数据需要和图元一起被组织进管线；而改变投影矩阵、切换状态这类命令不属于顶点数据，写在块里是非法的。

    因为颜色是逐顶点设置并且可以变化，所以同一个图元内不同顶点可以有不同颜色，光栅化时会在顶点之间做颜色插值，得到渐变效果：

    ```c
    glBegin(GL_POLYGON);
        glColor3f(1.0, 1.0, 0.0); glVertex3f(0.0, 0.0, 0.0);
        glColor3f(0.0, 1.0, 1.0); glVertex3f(5.0, 0.0, 0.0);
        glColor3f(1.0, 0.0, 1.0); glVertex3f(0.0, 5.0, 0.0);
    glEnd();
    ```

    这解释了颜色数组为什么有意义：颜色本质上是和顶点绑定的属性，不是图元的属性。

7. **多边形显示模式与面剔除**

    `glPolygonMode(face, mode)` 控制多边形怎么画：

    - face 可以是 `GL_FRONT`、`GL_BACK`、`GL_FRONT_AND_BACK`；
    - mode 可以是 `GL_FILL` 填充、`GL_LINE` 只画边、`GL_POINT` 只画顶点。

    默认前后两面都填充。把 mode 设为 `GL_LINE` 就是常见的线框模式，调试几何体时很常用。这里的`glPloygonMode(face,mode)`是渲染状体而不是集合数据以及顶点属性，它的作用是告诉管线怎么处理图元。

    面的正反由顶点绕序决定，`glFrontFace` 设置绕序，默认 `GL_CCW` 表示逆时针绕序为正面。为什么默认逆时针：从物体外部看过去，逆时针绕序的顶点围成的面朝向观察者，这是右手系的约定。

    剔除背面的流程是两步，先 `glCullFace` 指定剔除哪一面，再 `glEnable(GL_CULL_FACE)` 打开剔除。只设置 `glCullFace` 而不打开开关是没有效果的，这是初学时常见的错误。背面剔除的价值在于封闭物体内部的面本来就看不见，提前丢掉能省一半光栅化工作量。

    > 这一部分中还有很多细节没有理解到...... 尤其是涉及到这个函数究竟该如何使用之类的

8. **辅助库里的现成物体**

    课件顺带提到，圆柱、圆锥、NURBS 曲面这类复杂形状由 GLU 提供构造函数，球与立方体由 GLUT 提供。它们本身不产生新的渲染能力，只是用三角形拼出网格再交给 OpenGL 画。

## GLUT 与事件驱动

1. **GLUT 程序的骨架**

    GLUT 的作用是补上 OpenGL 不管的那部分：窗口创建、事件监听、主循环。程序结构固定为：初始化 GLUT，设置显示模式，创建窗口，注册回调函数，进入主循环。

    所谓的glut进行回调函数的注册，就是将这个函数加入loop这个调度器里面，

    ```c
    int main(int argc, char **argv)
    {
        glutInit(&argc, argv);
        glutInitDisplayMode(GLUT_RGBA | GLUT_DOUBLE);
        glutCreateWindow("Simple GLUT App");
        glutDisplayFunc(redraw);
        glutMainLoop();
        return 0;
    }
    ```

    注意显示模式里的 `GLUT_DOUBLE` 表示双缓冲：绘制发生在后台缓冲，画完后用 `glutSwapBuffers` 与前台缓冲交换，这样画面不会看到画一半的中间状态。

2. **事件驱动模型**

    实际上，我们的窗口程序的控制权一直在窗口系统中，而不在main函数里。窗口程序不同于普通的main程序，从头执行到尾结束，它处理的是异步事件。需要了解用户什么时候按键、什么时候拖动窗口、系统什么时候重画，这些是由外部事件决定的，代码无法预知。所以窗口程序只做两件事：

    1. 告诉系统在发生上述事件时通知自己；
    2. 等待系统通知自己；

    这两件事对应到GLUT，前者就是注册函数，后者是glutMainLoop。

    glutMainLoop就是主循环，它从main从接管控制权，之后不会再返回到main，所有事件分发都在这里面完成。而我们的注册函数，其实就是分配处理函数。每个事件类型都有一个槽位，我们把自己的函数放进去，下一轮该事件的处理就是执行我们的函数。比如说：

    ```c
    void display(void){
    	glClear(GL_COLOR_BUFFER_BIT);
        /* 具体画的内容 */
    }
    int main(int argc, char **argv){
        glutInit(&argc,argv);
        glutInitDisplayMode(GLUT_DOUBLE | GLUT_RGB);
        glutCreateWindow("demo");
        glutDisplayFunc(display);//分配到我们的display函数
        ... //其他的注册函数绑定；
        glutMainLoop;//开始执行GLUT事件循环
        return 0;
    }
    ```

    我们最开始将重绘的回调分配给了我们的`display`函数，进入主循环后，进行阻塞等待，直到事件到来驱动。

    关于回调，有几点注意事项：

    - 注册函数的分配不是绑定关系，是可以进行变化的。main函数中的分配一般是提供一个初始的入口，在具体的函数操作中可以调整不同的操作分配完成不同的效果。
    - 被分配的具体函数要满足对应的返回类型和参数类型，所有回调都返回`void`，但是参数还有区别

    以下列出常见的一些注册函数：

    | 槽位     | 注册函数                | 函数签名                                      | 触发时机                                                     |
    | -------- | ----------------------- | --------------------------------------------- | ------------------------------------------------------------ |
    | 显示     | `glutDisplayFunc`       | `void f(void)`                                | 窗口第一次显示、这档后恢复、尺寸变化。自己主动进行的画面改动需要主动调用`glutPostRedisplay`请求重绘 |
    | 尺寸变化 | `glutReshapeFunc`       | `void f(int w, int h)`                        | 用户拉伸窗口时触发                                           |
    | 普通按键 | `glutKeyboardFunc`      | `void f(unsigned char key, int x, int y)`     | 按键的ASCII码，这里只有按下处理，没有松开处理                |
    | 特殊键   | `glutSpecialFunc`       | `void f(int key, int x, int y)`               | 上下左右、F1、F12等                                          |
    | 鼠标按键 | `glutMouseFunc`         | `void f(int button, int state, int x, int y)` | 左右键、滚轮等，按下和松开各触发一次，靠state区分            |
    | 拖动     | `glutMotionFunc`        | `void f(int x, int y)`                        | 鼠标处于按下状态并且鼠标移动                                 |
    | 悬停     | `glutPassiveMotionFunc` | `void f(int x, int y)`                        | 没有按键时鼠标移动                                           |
    | 进出窗口 | `glutEntryFunc`         | `void f(int state)`                           | state：离开和进入窗口                                        |
    | 可见性   | `glutVisibilityFunc`    | `void f(int state)`                           | state：是否被其他窗口完全遮挡                                |
    | 空闲     | `glutIdleFunc`          | `void f(void)`                                | 事件队列为空时被调用，频率不固定。动画一般都放在idle回调里   |
    | 定时     | `glutTimerFunc`         | `void f(int value)`                           | 回调只触发一次，要重复需要在回调中调`glutTimeFunc`           |
    | 菜单选择 | `glutCreateMenu`        | `void f(int value)`                           |                                                              |

3. **窗口尺寸变化时为什么要重设投影**

    重绘回调里必须重新设置视口和投影矩阵：

    ```c
    void reshape(int w, int h)
    {
        glViewport(0, 0, w, h);
        glMatrixMode(GL_PROJECTION);
        glLoadIdentity();
        glOrtho(0.0, w, 0.0, h, -1.0, 1.0);
        glMatrixMode(GL_MODELVIEW);
        glLoadIdentity();
    }
    ```

    原因是 `glViewport` 决定了规范化设备坐标映射到窗口的哪一块像素区域，如果不随窗口更新，图形会被拉伸或者只占窗口一角。而 `glOrtho` 把用户坐标范围对上窗口的像素范围，不重设的话，缩放后图形的比例会失真。

    课件里的旋转方块例子还展示了鼠标状态控制的写法：按下左键时注册 `spinDisplay` 作为空闲回调开始旋转，按下右键时传 `NULL` 取消空闲回调停止旋转。这就是用事件改变程序状态、再由主循环驱动动画的典型做法。

4. **其他接口细节**

    - 只需要包含 `<GL/glut.h>`，它会把 `gl.h` 和 `glu.h` 一并包含进来；编译时还必须把 glut 的库文件与动态库放进搜索路径，否则链接会失败。
    - 窗口位置和大小可以在运行时用 `glutPositionWindow` 与 `glutReshapeWindow` 调整。
    - GLUT 的鼠标坐标原点在窗口左上角，y 轴向下，而 OpenGL 的窗口坐标原点在左下角，y 轴向上，所以回调里通常要写 `winHeight - y` 把 y 翻过来。课件里的鼠标回调就是这么做的。
    - 三种缓冲区相关的常量要分清：`GLUT_SINGLE` 与 `GLUT_DOUBLE` 决定单缓冲还是双缓冲，`GLUT_RGB` 与 `GLUT_RGBA` 决定是否带 alpha，`GLUT_DEPTH` 申请深度缓冲。没有申请深度缓冲却打开深度测试，遮挡关系会完全错误。

## 颜色

1. **为什么用 RGB**

    因为显示器硬件的物理发光单元都是RGB三基色这三种，选择其他三基色理论上也能构成完整色域，但和现有硬件不匹配，需要额外做颜色空间转换。

2. **人眼的锥细胞** conts

    人眼视网膜上的三类锥细胞的敏感峰值分别近似对应到蓝、绿、红三种颜色，这三种细胞的响应强度组合起来就是人眼感知到的颜色，这也说明了RGB设定的合理性

3. **颜色模型与颜色查找表**

    颜色可以用这几种方式组织：

    - 直接存 RGB 分量，即真彩色；
    - 存颜色索引，真实颜色放在一张颜色查找表里，索引值指向表中的某一项；
    - 灰度，三个通道取同一个值。

    索引模式的优点是省显存，一个像素只存一个字节的索引而不是三个字节的分量；缺点是同一画面能同时出现的颜色数受查找表大小限制，改一个颜色要改整张表。现代硬件基本都是真彩色，索引模式只在早期显卡和某些纹理格式中还能见到；

4. **OpenGL 颜色命令**

    - `glColor3f(1.0, 1.0, 1.0)`：浮点分量，范围 0 到 1；
    - `glColor3i(0, 255, 255)`：整数分量，范围 0 到 255；
    - `glColor3fv(colorArray)`：用数组传三个分量；
    - 带 4 个分量的版本多一个 alpha 通道，用于透明度。

    显示模式上的 `GLUT_RGB` 与 `GLUT_RGBA` 区别就在于帧缓冲是否保留 alpha 通道。要做透明混合就必须用 `GLUT_RGBA`。

5. **索引模式与混合**

    索引模式下用 `glIndexi(196)` 设置当前颜色索引，实际颜色由颜色查找表决定。混合模式下用：

    ```c
    glEnable(GL_BLEND);
    glBlendFunc(sFactor, dFactor);
    ```

    `glBlendFunc` 决定源颜色和目标颜色各按什么权重参与合成，常见的有源 alpha 与 1 减源 alpha 的组合。混合需要关闭深度写入或者仔细安排绘制顺序，否则透明物体的前后关系会出错。

6. **颜色数组**

    颜色也能像顶点一样组织成数组，一次提交多个颜色：

    ```c
    glEnableClientState(GL_COLOR_ARRAY);
    glColorPointer(...);
    glEnableClientState(GL_VERTEX_ARRAY);
    glVertexPointer(...);
    ```

    这两个 `EnableClientState` 打开的是客户端状态，含义是告诉 OpenGL 顶点数据和颜色数据放在应用内存里，由驱动按需读取。这已经是顶点数组时代的接口，和前面 `glBegin` 的立即模式属于两代不同的组织方式。

## 点、线、面的属性

1. **点的属性**：尺寸与颜色。尺寸由 `glPointSize` 设置，颜色由 `glColor` 设置。点的大小在屏幕上通常以像素为单位，超过一定尺寸后点的形状会成为问题，因为默认点只是方形的像素块。

2. **线的属性**：线宽、线型、画刷。

    - 线宽由 `glLineWidth` 设置。线宽大于 1 时，光栅化不再是简单的 Bresenham，而要考虑如何把一条有宽度的带子铺到像素上，不同硬件对粗线的支持差异很大。
    - 线型指实线、虚线、点划线，由 `glLineStipple` 用 16 位模式加重复因子控制，本质是沿参数方向按周期决定这一段画不画。
    - 画刷指用图案而不是纯色去画线，这在绘图软件里常见，硬件管线一般不支持，需要软件实现。

3. **区域属性**：区域由平面多边形定义，填充样式有三种。

    - 线框，只画边界；
    - 实心填充，内部全部涂色；
    - 图案填充，用一张瓦片图案平铺内部。

    这三种正好对应 `glPolygonMode` 的不同模式加上不同的纹理或图案来源。

## 区域填充的扫描线实现

课件从多边形表示的两种形式讲起，然后给扫描线算法的工程细节。

1. **两种表示**

    - 顶点表示：只存边界顶点的坐标序列。便于做几何变换，但不知道内部哪些像素要涂。
    - 点阵表示：直接存内部像素集合，也就是帧缓冲里的实际形态。

    填充的本质就是把顶点表示转换成点阵表示，中间必须做内外测试。

2. **内外测试回顾**

    课件在这一页提出两个问题：如何判断点在多边形内，以及如何改进判断效率。答案是奇偶测试与环绕数测试，以及用扫描线利用连贯性。具体原理 ch2 已经详细写过，这里只记住结论：

    - 奇偶测试：从待测点引射线，交点数为奇数则在内部；
    - 环绕数测试：沿边界走一圈，累计有向角，非零则在内部。

    两者数学上都正确，但对每个像素独立计算代价太高，复杂度是多边形边数乘以像素总数。真正的填充算法不这么算。

3. **一致性**

    扫描线方法的核心是两条一致性：

    - 空间一致性：除了边界附近，相邻像素大概率具有相同属性，所以不需要逐像素判断；
    - 扫描线一致性：相邻扫描线上的像素分布大概率相似，所以上一条扫描线的交点信息可以复用。

    利用连贯性，一条扫描线只需要求出它与多边形边界的交点，把交点按 x 排序，两两配对，配对区间内的像素整段填色。这样判断从逐像素降到了逐交点。

4. **算法步骤**

    - 求当前扫描线与多边形所有边的交点；
    - 把交点按 x 坐标升序排序；
    - 相邻两个交点之间的一段像素填充指定颜色。

    配对填充的依据就是奇偶规则：从左往右走，进入多边形时是第 1 个交点，离开时是第 2 个，再进入是第 3 个。所以排序后按顺序两两成对即可，不需要对每个像素单独做判断。

5. **边连贯性与增量更新**

    这是扫描线算法效率的关键。一条边在相邻两条扫描线上的交点 x 坐标满足线性关系：

    $$x_{i+1} = x_i + \frac{1}{m}$$

    其中 m 是这条边的斜率 $\Delta y / \Delta x$，所以 $\frac{1}{m}$ 就是 $\frac{\Delta x}{\Delta y}$，也就是 y 每增加 1 时交点 x 的增量。执行时从上往下逐行扫描，y 每加 1，交点 x 就累加这个增量，每条边在一条扫描线上因此只需要一次加法，不用解一次直线方程。

    进一步的做法是维护活性边表。把边按最小 y 排序放进边表，扫描到某一行时，只有跨过这一行的边才进入活性边表；活性边表内部按当前交点 x 排序。每换一行，先删掉已经结束的边，再加入新跨入的边，然后对每条边做一次 x 增量更新。排序也只需要在局部维护，因为边之间的相对顺序很少改变。

    课件还提了两点效率优化方向：多边形是凸的时候，活性边表最多只有两条边，处理可以大幅简化；如果图元都是三角形，边数更少，配合硬件并行效果最好。这也解释了为什么图形硬件最终只认三角形。

6. **顶点与水平边的特殊情况**

    扫描线经过多边形顶点时，交点数不能机械地按边数统计，否则会填错。课件给的规则：

    - 局部极值点，也就是两条边在顶点处分别位于扫描线两侧，这个顶点要算两个交点。图中 I1、I2 就属于这类，如果不算两次，配对会错位，导致内部被填成外部。
    - 普通穿越点，两条边在顶点的同一侧，只算一个交点。图中 I3 属于这类。
    - 水平边不参与交点计算，直接跳过。因为水平边与扫描线重合，交点是无穷多个，无法用单个交点表示，跳过它不影响配对结果。

    实现上的常用技巧是：统计交点时只考虑边的下端点，也就是把每条边的 y 范围取成半开区间 $[y_{min}, y_{max})$。这样每个顶点恰好只被一条边计入一次，局部极值自然算两次，普通穿越自然算一次，水平边两端点 y 相等，自然被排除。这个技巧比逐个判断顶点类型简单得多，考试里也常考。

7. **扫描线方法的优点**

    - 效率高，每个像素只访问一次；
    - 便于和着色算法结合，因为按扫描线处理时可以顺便做光照插值，Gouraud 着色和 Phong 着色都是在这个结构上做的；
    - 只需要维护很小的数据结构，内存开销低。

8. **种子填充**

    另一种思路是种子填充，前提是已知多边形内部至少一个像素。

    - 从种子像素出发，检查它的相邻像素，如果相邻像素在多边形内部且未被填充，就填色并把它作为新的种子递归下去；
    - 按邻域定义分为 4 连通与 8 连通。4 连通只看上下左右，8 连通额外看四个对角方向。

    4 连通和 8 连通的选择必须和边界的连通性匹配，否则会出现填充漏到区域外，或者边界本身被填掉的情况。种子填充是递归算法，实现简单，交互式绘图软件里的油漆桶工具用的就是这类算法。缺点是递归深度可能很大，实际实现要用栈或者扫描线种子填充来避免栈溢出。

## 走样与反走样

1. **走样的本质**

    显示设备是离散的像素网格，光栅化本质上是用有限个采样点去采样一个连续信号，也就是点采样。当采样率不足以表达信号的高频细节时，信息就会丢失并且以错误的形式重现，这种采样误差就叫走样。

    用信号处理的语言说：连续图形有无限细节，像素网格是冲激采样，采样频率低于信号最高频率的两倍时发生频谱混叠。

2. **走样的三种表现**

    - 锯齿边缘：斜线或曲线边界上出现阶梯状像素，因为边界只能落在像素中心；
    - 细节错误渲染：细密的纹理或图案在缩小时出现本来不存在的条纹，即摩尔纹；
    - 小物体丢失：比像素还小的物体可能正好落在采样点之间，于是整个消失。动画中表现为远处物体闪烁。

    课件用三页展示了锯齿、摩尔纹和细节丢失的实例，这三类现象都源于同一个原因。

3. **反走样的目标与三条路线**

    反走样是减少或消除走样痕迹的技术总称。课件给出三类方法：

    - 提高采样率，也就是提高分辨率。分辨率翻倍，显存需求变为四倍，因为像素总数是平方增长。这是最直接也最贵的方法，只能缓解不能根除。
    - 后置滤波，也叫平均法。像素的最终强度取它自己和周围像素强度的加权平均。这相当于对已经光栅化的图像做一次低通滤波，能柔化锯齿，但会整体变模糊，而且丢失的细节找不回来。
    - 区域采样，课件认为这是更常用的方法。

4. **区域采样**

    区域采样不再把像素看成一个点，而看成一个有限面积的小方块。图元覆盖这个方块的比例决定了这个像素的颜色权重，这叫加权面积采样。

    具体做法是估计像素被图元覆盖的百分比：

    - 把像素细分成若干子像素，统计有多少个子像素落在图元内部，用比例作为覆盖率。子像素越多越精确，代价也越大。
    - 对直线来说可以把增量算法扩展一下，沿扫描线推进时记录直线在像素内的实际位置，直接算出被填充的面积。课件给的示意是用 $y+0.5$ 与 $y-0.5$、$x+0.5$ 与 $x-0.5$ 围出的方块，直线穿过它时切割出的面积就是该像素的覆盖比例。

    覆盖率算出后，边界像素的颜色取图元颜色与背景颜色的加权混合，权重就是覆盖率。这样斜线边缘会出现中间色调的像素，视觉上就是平滑过渡。

    区域采样和超采样在思想上是一回事，区别在于超采样是在更大的缓冲里按更高分辨率光栅化再降采样，区域采样是在单个像素内部解析地估计覆盖率。前者实现简单通用，后者精度高但需要针对图元类型写不同的面积公式。

5. **深度学习反走样**

    课件最后提到了两条现代路线：

    - DLSS，深度学习超分辨率。低分辨率渲染再用神经网络放大，重点在性能，用少量画质损失换取帧率。它依赖 RTX 显卡上的 Tensor Core 做矩阵运算。
    - DLAA，深度学习反走样。在原生分辨率下运行，不做缩放，重点在画质，用神经网络替代传统的时域反走样来消除锯齿。

    两者的区别可以这样记：DLSS 解决的是渲染分辨率低导致的画质问题，DLAA 解决的是分辨率足够但边缘仍有锯齿的问题。它们都需要 Tensor Core，因此是硬件绑定的方案。

## 裁剪

1. **为什么要裁剪**

    裁剪发生在光栅化之前，把不在显示范围内的内容去掉。课件给出两个理由：

    - 扫描转换只需要处理裁剪后的图元，而裁剪后的图元可能比原来小得多，光栅化的工作量因此下降；
    - 图元通常定义在实数世界坐标里，映射到整数的显示坐标时可能溢出整数范围，产生不可预期的伪影。比如一个端点在一百万个单位之外的线段，映射后坐标溢出，画出来就是乱线。

    裁剪的另一个隐含理由是正确性：视锥外的几何本来就不该出现在画面上，不裁剪直接光栅化还可能因为数值问题画到屏幕边缘。

2. **裁剪的定义**

    裁剪就是移除不会显示的内容。以相机为参照，不会显示的内容包括：

    - 在相机后面；
    - 离相机太近，进入近裁剪面以内；
    - 太远，超出远裁剪面；
    - 在屏幕的左右上下之外。

    二维裁剪的裁剪窗口是一个正放的矩形，这在窗口系统里最常见。点的裁剪最简单，判断 $x_{min} \le x \le x_{max}$ 且 $y_{min} \le y \le y_{max}$ 即可。真正需要算法的是线段和多边形。

3. **Cohen-Sutherland 线段裁剪**

    核心思想是用四位编码表示端点相对裁剪窗口的位置，先做快速的整段接受或整段拒绝，只在无法判断时才求交点。

    编码规则，每一位对应一条边界：

    | 位 | 值 | 含义 |
    | --- | --- | --- |
    | 第 0 位 | 1 | 点在左边界的左侧 |
    | 第 1 位 | 2 | 点在右边界的右侧 |
    | 第 2 位 | 4 | 点在下边界的下方 |
    | 第 3 位 | 8 | 点在上边界的上方 |

    于是九个区域的编码如下：

    ```
    1001 | 1000 | 1010
    0001 | 0000 | 0010
    0101 | 0100 | 0110
    ```

    编码 0000 表示点在窗口内部。注意编码是按位或得到的，所以一个点可以同时有多个位为 1，例如左上角是 1001。

    判断分四种情况：

    - 两个端点编码都是 0，整条线段在内部，直接接受。这对应按位或等于 0。
    - 两个端点编码按位与不为 0，说明两端在同一侧的外部，整条线段必然在外部，直接拒绝。例如两端都在左侧，与运算得到第 0 位为 1。
    - 一个端点在内部编码为 0，另一个在外部，用外部端点的编码找出它穿过的边界，求出交点并替换外部端点，然后重新编码继续判断。这种情况最多做两次。
    - 两个端点都在外部但按位与为 0，说明两端在不同侧，线段可能穿过窗口也可能不穿过。同样求交点替换，反复迭代，直到接受或拒绝。

    求交点的公式按边界选：

    - 穿过上边界时，$y = y_{max}$，$x = x_0 + (x_1 - x_0)\frac{y_{max} - y_0}{y_1 - y_0}$；
    - 穿过下边界时，$y = y_{min}$，x 用同一公式把 $y_{max}$ 换成 $y_{min}$；
    - 穿过右边界时，$x = x_{max}$，$y = y_0 + (y_1 - y_0)\frac{x_{max} - x_0}{x_1 - x_0}$；
    - 穿过左边界时，$x = x_{min}$，y 用同一公式把 $x_{max}$ 换成 $x_{min}$。

    算法的循环体可以写成：

    ```c
    while (1) {
        if (!(o1 | o2)) { accept = true; break; }
        if (o1 & o2) break;              // 整段拒绝
        outcodeOut = o1 ? o1 : o2;       // 取外面的那个端点
        // 用 outcodeOut 的最高位决定求交的边界，算出交点 (x, y)
        if (outcodeOut == o1) {
            x0 = x; y0 = y; o1 = ComputeOutCode(x0, y0);
        } else {
            x1 = x; y1 = y; o2 = ComputeOutCode(x1, y1);
        }
    }
    ```

    每次迭代都把至少一个位于外部的端点替换成边界上的交点，被替换的端点不再处于原来的外侧，编码里为 1 的位只会减少，所以循环必然终止。最坏情况下要迭代几次，课件说可能是四次，具体取决于线段穿过窗口的路径。

    这个算法的优点是两端都在内部或都在同一侧外部时，判断只需要几次位运算，完全不用除法。只有真正穿过边界的线段才付求交的代价。缺点是当线段很短、大部分都在窗口外时，仍然要迭代多次，且每次都要做除法。

4. **Liang-Barsky 算法**

    Cohen-Sutherland 的问题在于反复求交、反复编码。Liang-Barsky 换了一个角度：把线段写成参数形式，把裁剪条件统一成四个不等式，一次性解出参数的合法区间。

    线段参数方程：

    $$x = x_0 + u\Delta x,\quad y = y_0 + u\Delta y,\quad u \in [0, 1]$$

    其中 $\Delta x = x_1 - x_0$，$\Delta y = y_1 - y_0$。点在窗口内部的条件是：

    $$x_{min} \le x_0 + u\Delta x \le x_{max}$$
    $$y_{min} \le y_0 + u\Delta y \le y_{max}$$

    这四个不等式统一写成：

    $$u p_k \le q_k,\quad k = 1,2,3,4$$

    对应关系如下：

    | k | 边界 | $p_k$ | $q_k$ |
    | --- | --- | --- | --- |
    | 1 | 左 | $-\Delta x$ | $x_0 - x_{min}$ |
    | 2 | 右 | $\Delta x$ | $x_{max} - x_0$ |
    | 3 | 下 | $-\Delta y$ | $y_0 - y_{min}$ |
    | 4 | 上 | $\Delta y$ | $y_{max} - y_0$ |

    每个不等式的几何含义很直接：比如左边界 $x \ge x_{min}$ 变形后是 $u(-\Delta x) \le x_0 - x_{min}$，当线段从左向右走时 $\Delta x > 0$，$p_1 < 0$，解得 $u \ge \frac{q_1}{p_1}$，这是对参数的下界约束。

    由此得到参数的更新规则：

    1. 初始化 $u_1 = 0$，$u_2 = 1$，分别表示可见段在参数轴上的起点与终点；
    2. 当 $p_k < 0$ 时，直线从窗口外走向内，这是进入边界，$u$ 的下界收紧，取 $u_1 = \max(u_1, q_k / p_k)$；
    3. 当 $p_k > 0$ 时，直线从窗口内走向外，这是离开边界，$u$ 的上界收紧，取 $u_2 = \min(u_2, q_k / p_k)$；
    4. 当 $p_k = 0$ 时，线段平行于该边界，若此时 $q_k < 0$，说明线段整体在边界外侧，直接舍弃；
    5. 任何一次更新后如果 $u_1 > u_2$，说明可见区间为空，舍弃该线段。

    全部四个边界处理完且未被舍弃，就用 $u_1$、$u_2$ 代入参数方程得到裁剪后的两个端点。

    课件把五条规则写得很细，可以直接对照记忆：$p_k = 0$ 表示平行，$q_k < 0$ 表示平行且在外部，$p_k < 0$ 表示从外到内，$p_k > 0$ 表示从内到外，$u = q_k / p_k$ 是交点参数。这五条就是整个算法的全部判断。

    和 Cohen-Sutherland 相比，Liang-Barsky 的优点是每个边界最多处理一次，四条边界各算一次交点参数，总共不超过四次除法，不需要迭代重编码；而 Cohen-Sutherland 的一条线段可能要迭代多次，每次迭代都要重新编码并做一次除法。代价是推导稍微复杂，需要理解参数区间的含义。

    课件把实现 Liang-Barsky 作为作业，说明这是必须能默写出来的算法。

5. **Sutherland-Hodgman 多边形裁剪**

    线段裁剪只要处理两个端点，多边形裁剪要处理整条边界链，关键是裁剪后多边形的顶点集合会变化，可能变多也可能变少。

    算法的思路是逐边裁剪：把窗口的四条边界看作四道关卡，多边形依次通过每一道，每通过一道就得到一个新的顶点表，作为下一道的输入。对某一条边界，只需要判断每个顶点在这条边界的内侧还是外侧。

    具体做法是把多边形的顶点按顺序排成环，取相邻的一对顶点 $(s, p)$，s 是前一个，p 是当前，然后按四种情况输出：

    - s 在内，p 在内：输出 p；
    - s 在内，p 在外：输出交点 i；
    - s 在外，p 在外：不输出；
    - s 在外，p 在内：先输出交点 i，再输出 p。

    为什么是这四种：裁剪的本质是保留内侧的部分。当线段从内走到外，保留到交点为止，所以输出交点，p 被丢掉；从外走到内，从交点开始才可见，所以交点和新端点都要输出。两端都在内，p 作为内侧点保留；两端都在外，这段完全不可见。

    课件用五边形 v1 到 v5 完整走了一遍。这个五边形里 v1、v2、v5 在边界内侧，v3、v4 在外侧，按顶点顺序取相邻对：

    - (v5, v1)：都在内，输出 v1；
    - (v1, v2)：都在内，输出 v2；
    - (v2, v3)：v2 在内，v3 在外，从内走到外，输出交点 i1；
    - (v3, v4)：都在外，不输出；
    - (v4, v5)：v4 在外，v5 在内，从外走到内，输出交点 i2 和 v5。

    最终顶点表是 v1、v2、i1、i2、v5，正好构成裁剪后的多边形，顶点顺序仍然沿着边界走一圈。这个例子也说明为什么起点对要取 (v_n, v_1)：i2 这条新边是在最后一对里补出来的，它连接了离开窗口的边和重新进入窗口的边，如果漏掉首尾对，这段补边就丢了。

    课件还提到流水线实现：因为多边形裁剪不依赖其他多边形，四条边界的裁剪可以串成流水线，前一级的输出直接作为后一级的输入，硬件里可以让四个多边形同时处于不同阶段。这是把算法结构映射到硬件的典型例子。

6. **两种裁剪的关系**

    线段裁剪和多边形裁剪的区别在于，多边形裁剪必须维护内外关系和顶点顺序。线段裁剪丢掉一段就完了，多边形裁剪如果只保留可见部分的端点，会失去多边形的封闭性，所以需要沿着窗口边界补上新的边。

    Sutherland-Hodgman 的缺点也在这里：它输出的顶点表可能包含共线的多余顶点，而且对凹多边形的裁剪结果如果是多个分离的区域，算法会把它们连成一条退化的边界，需要用额外的边连接起来。实际实现里通常会在裁剪后做一次清理，去掉重复点和共线点。

## 本章脉络

把整章串起来看，逻辑是一条线：

1. 要画东西，先要知道 OpenGL 有哪些图元，以及如何用顶点和 `glBegin` 组织它们；
2. 同样的几何形状要长出不同的样子，靠的是属性参数，而属性参数由状态机统一管理；
3. 颜色是最基本的属性，它的三通道模型来自人眼锥细胞和显示器的物理结构；
4. 区域的填充要把顶点表示转成点阵表示，扫描线算法利用连贯性把这个转换做到线性复杂度；
5. 光栅化是点采样，必然走样，反走样要么提高采样率，要么估计覆盖率；
6. 光栅化之前要裁剪，线段用编码法或参数法，多边形用逐边裁剪法。

考试里最可能出计算题的是 Cohen-Sutherland 的编码与求交、Liang-Barsky 的 p、q 推导与参数更新、Sutherland-Hodgman 的四情况输出表。最可能出简答题的是走样的成因与三种反走样方法的比较、扫描线算法的连贯性来源与顶点特殊情况的处理。Liang-Barsky 的实现是课件明确布置的作业，必须能独立写出可运行的版本。
