# ch3

## 续ch2

1. **视口与坐标系统**

    在图形程序中，图形数据从世界坐标映射到屏幕显示，涉及不同层次的窗口与坐标系统定义：

    - 窗口概念的双重含义：
      - 操作系统视角下的显示窗口：操作系统分配给图形应用程序的物理客户区，具有明确的像素分辨率，受窗口管理系统调度。
      - 虚拟世界视角下的观察窗口：在三维或二维虚拟场景中指定的矩形视野区域，定义了观察者能看到虚拟世界中的哪一部分场景。
    - 视口（Viewport）：
      - 视口是应用程序显示窗口内部实际用于绘制画面的矩形子区域。默认情况下视口大小与窗口大小重合，但也可以将视口设置为窗口的局部区域，例如分屏显示或小地图。超出视口边界的图元像素会被硬件裁剪丢弃，不会渲染到屏幕上。
    - 坐标系转换与映射：
      - 用户坐标系是浮点数坐标，允许开发者自由定义现实世界物体的长宽尺寸。
      - 视口坐标系是与帧缓冲区一一对应的非负整数坐标，直接对应物理像素格子。图形系统负责将用户坐标空间中的几何图元线性缩放并平移映射到视口区域内。

2. **像素坐标约定与区域图元光栅化规则**

    在离散像素网格上光栅化多边形等区域图元时，必须建立严谨的数学坐标对齐标准：

    - 像素中心半整数约定：
      - OpenGL 规定，像素网格的边界线位于整数坐标处，而像素的几何采样中心位于半整数坐标位置，即 $(x + 0.5, y + 0.5)$。
      - 例如左下角第一个像素格子的范围是 $[0, 1] \times [0, 1]$，其对应的采样点中心坐标为 $(0.5, 0.5)$。
    - 区域图元包含判定规则：
      - 当且仅当某个像素的几何采样中心严格落在多边形区域内部时，硬件光栅化器才会为该像素生成片元。
    - 共享边界处理规则（Left-Bottom 准则）：
      - 难点解释与例子：当两个相邻三角形紧密拼合、共用一条公共边时，位于公共边上的像素中心恰好落在几何分界线上。如果两个三角形都认为该像素属于自己并进行绘制，在半透明混合或深度测试时就会出现像素重复绘制、产生多余暗纹；反之如果都不绘制，接缝处就会出现一条透出背景色的裂缝。
      - 解决机制：OpenGL 等图形系统规定了统一的边界归属法则，通常只绘制多边形的左边界和底边界。如果像素中心落在顶边界或右边界上，则判定为不属于当前多边形。这种规则严格保证了任意紧邻拼接的多边形在光栅化时，接缝处的每一个像素都被且仅被其中一个多边形绘制一次，实现无缝且无重叠的渲染。

3. **图形渲染管线基础模型**

    现代计算机图形系统将三维几何数据转换为二维屏幕画面的处理过程抽象为一个线性的流水线结构，核心阶段包括：

    - 逐顶点操作（Per-vertex operations）：接收应用程序传入的模型几何顶点，执行模型视点变换与投影变换，将三维坐标变换到规范化设备坐标系中，并计算顶点的光照颜色或法向量。
    - 图元装配（Primitive Assembly）：根据图元类型指令，将处理后的离散顶点重新组合装配为点、线段或多边形网格，并在此阶段执行视锥体裁剪。
    - 光栅化（Rasterization）：将连续的几何图元网格分解并覆盖到离散的像素格子上，产生一系列候选片元（Fragments）。片元不仅包含屏幕像素坐标，还包含了该位置插值得到的深度值、颜色、纹理坐标和法线向量。
    - 逐片元操作（Per-fragment operations）：根据插值得到的数据执行纹理采样、光照着色计算，并依次通过裁剪测试、Alpha 测试、模板测试和深度测试，剔除被遮挡的无效片元。
    - 帧缓冲操作（Frame buffer operations）：将最终通过各项测试的片元颜色值与帧缓冲区中已有像素进行混合或覆盖写入，完成整幅画面的生成。

## OpenGL

1. 认识OpenGL：一个用于图形渲染的跨平台软件接口标准，它不是具体的图形库实现，而是一套跨语言跨平台的规范。向下负责屏蔽不同显卡硬件的底层差异，并调用硬件加速，向上为应用程序提供统一的图形渲染API
2. 现代图形API演进：OpenGL最初是单线程状态机架构，显卡驱动程序承担了大量的运行状态校验、显存调度等，导致驱动层高开销；现代图形平台比如Vulkan、Metal，它们将显存分配和指令缓冲架构的控制权下放给应用程序，能获得更高的并发性能以及更低的驱动层开销
3. 核心架构：状态机。
    - 应用程序通过API设置状态变量，比如画笔颜色，光照模式等等。
    - 每个状态变量初始化时都有系统默认值
    - 当状态被激活它将一直保持生效，并影响后续所有的图元绘制，直到下一次状态修改的到来。
4. 功能范围
    - 只绘制几何图元并渲染成图像，不能完成窗口创建、键盘鼠标事件监听以及音频控制等与具体操作系统紧密绑定的功能，这些依赖于其他的工具包。
    - **GLUT(OpenGL Utility Toolkit)**，OpenGL实用工具包，用来负责窗口创建和管理，键盘鼠标监听，窗口大小调整等行为；
    - GLU，实用库，用来进行一些复杂对象的生成，比如球体、圆柱体等；

### 工具链

1. 核心库，头文件为`<GL/gl.h>`，包含核心指令集合；
2. 实用库（GLU）：头文件`<GL/glu.h>`，在核心库上封装的高级功能，可以进行一些复杂对象的生成，还有相机观察矩阵计算工具等；
3. 实用工具包（GLUT）：头文件为 `<GL/glut.h>`，负责跨平台的窗口创建，事件监听，主事件循环调度等

### API 命名规范

1. 函数命名以 `gl`、`glu` 或 `glut` 开头，采用小驼峰命名，例如 `glVertex3f`。
2. 常量与宏定义全部以 `GL_`、`GLU_` 或 `GLUT_` 开头的大写字母及下划线组成，例如 `GL_COLOR_BUFFER_BIT`。
3. 数据类型以 `GL` 开头，例如 `GLfloat`, `GLint`, `GLenum`。
4. 函数后缀标明参数数量与数据类型：例如 `glVertex3f` 表示该函数接收 3 个 float 类型的浮点参数；`glVertex3fv` 中的 `v` 表示参数以数组指针形式传入。

### 基本几何图元

OpenGL 中所有复杂三维模型最终都拆解为三类基本几何图元：

- 点与线图元：
  - `GL_POINTS`：离散的点序列。
  - `GL_LINES`：独立的线段，每两个顶点组成一条互不相连的线段。
  - `GL_LINE_STRIP`：相连的折线段，首尾相接但不闭合。
  - `GL_LINE_LOOP`：闭合的折线环，最后一个顶点会自动连回第一个顶点。
- 多边形与三角网格图元：
  - `GL_TRIANGLES`：独立的三角形集合，每三个连续顶点构成一个三角形。
  - `GL_TRIANGLE_STRIP`：三角形带，除了前三个顶点构成第一个三角形外，之后每增加一个顶点就与前两个顶点组成一个新的相邻三角形，大大减少冗余顶点数据传输。
  - `GL_TRIANGLE_FAN`：三角形扇，所有三角形共享第一个公共中心顶点。
  - `GL_QUADS` 与 `GL_QUAD_STRIP`：独立四边形与四边形带。
  - `GL_POLYGON`：单凸多边形。
- 多边形有效性限制：
  - OpenGL 规范要求绘制的多边形必须满足四个几何条件：所有顶点共面、简单不自交、完全闭合、且必须是凸多边形。凹多边形在光栅化分解时可能产生不可预期的拓扑错误。
- 面显示模式与背向剔除：
  - 环绕方向定义正面：OpenGL 默认采用逆时针环绕（CCW）的顶点顺序定义为多边形朝向观察者的正面，顺时针（CW）定义为背面。可通过 `glFrontFace` 显式设置。
  - 显示模式控制：通过 `glPolygonMode` 可以将多边形的前面、背面分别指定以点集（`GL_POINT`）、线框（`GL_LINE`）或实体填充（`GL_FILL`）方式呈现。
  - 背向面剔除（Cull Face）：在封闭三维实体中，背向观察者的多边形必定会被前表面的实体遮挡。调用 `glEnable(GL_CULL_FACE)` 并配合 `glCullFace(GL_BACK)`，可以在光栅化之前将不可见的背向多边形直接丢弃，节约着色与深度测试的计算开销。

### GLUT 事件驱动程序设计与双缓冲机制

GLUT 采用典型的事件驱动设计范式，应用程序将各功能函数注册到框架中，由主循环统一派发执行。

- 核心事件回调函数：
  - 绘制回调（`glutDisplayFunc`）：当窗口需要重绘（例如首次弹出、被遮挡后重新显示或调用重绘请求）时被框架自动调用。
  - 视口重塑回调（`glutReshapeFunc`）：当用户手动拖动改变窗口大小时被调用。函数内部重新设定 `glViewport` 视口矩阵以及 `glOrtho` 投影矩阵，保证画面不会因窗口拉伸而发生几何长宽比例畸变。
  - 鼠标回调（`glutMouseFunc`）与移动回调（`glutMotionFunc`）：响应鼠标按键按下、释放以及按住拖动的屏幕交互事件。
  - 键盘回调（`glutKeyboardFunc`）：响应普通字符键以及功能键的按击事件。
  - 空闲回调（`glutIdleFunc`）：当操作系统没有待处理的外部输入事件时持续调用的函数，通常在其中改变旋转角度、物理位移等连续动画变量，并在末尾调用 `glutPostRedisplay()` 通知窗口调度下一帧刷新。
- 双缓冲交互机制（Double Buffering）：
  - 单缓冲的缺陷：在单缓冲模式下，所有的几何图元都是直接绘制在显示器正在读取扫描的同一个显存区域中。如果场景图元复杂、绘制用时较长，显示器扫描速度与显卡绘制不同步，用户屏幕上就会看到物体逐个闪现甚至画面横向撕裂。
  - 双缓冲的工作方式：系统在显存中开辟两个相同规格的缓冲区。前缓冲区的内容直接送往显示器扫描显示，后缓冲区对用户完全隐蔽，GPU 将新一帧画面的所有图元全部绘制在后缓冲区中。当后缓冲区绘制完毕，且显示器恰好完成一帧扫描时，程序调用 `glutSwapBuffers()` 交换前后缓冲区指针。此机制彻底消除了屏幕闪烁与残影撕裂，是实现流畅交互动画的基础。
